Evaluation model

Correct output is necessary. It is not sufficient.

An engineering agent must produce the right result, take a defensible path, behave reliably, and stay inside its permitted blast radius.

01

Outcome

  • Business-rule fidelity
  • API and database state
  • UI behavior
  • Security invariants
02

Trajectory

  • Tool selection
  • Handoffs and approvals
  • Evidence grounding
  • Retry behavior
03

Reliability

  • Repeated trials
  • Pass@k and all-k
  • Failure clusters
  • Confidence intervals
04

Efficiency and safety

  • Tokens and latency
  • Scope violations
  • Secrets and network
  • Human escalation
